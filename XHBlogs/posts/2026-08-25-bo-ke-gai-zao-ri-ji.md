# 博客改造日记:音乐、名片与评论系统踩坑记

今天一口气给博客做了好几件事,从早折腾到晚。记录一下都干了啥,还有踩过的坑,免得以后忘了。

## 1. 首页音乐卡片

给首页加了一个音乐播放器,进站自动播放《太聪明》(陈绮贞)。

- 用 `AutoPlayMusic.tsx` 挂了个自动播放的 `<audio>` 标签
- 音乐文件放 `public/bg-music.mp3`

一开始首页那个格子里显示 "NO MUSIC AVAILABLE" 占位文字,后来把它改成了封面图,点击还能暂停/播放,观感好了不少。

## 2. 封面图:从专辑封面到动漫装饰图

第一个版本用的是专辑封面,但专辑封面是方形的,而首页那个格子是**横向长方形**,放进去要么裁掉、要么留白,怎么都别扭。

后来干脆用 AI 生成了一张动漫风格的装饰图(竖版),再通过图生图重绘成**横版 1216×732**,然后用 Pillow 转成 jpg、裁掉右下角的 AI 水印,整张铺满格子。

折腾下来学会了一招:**AI 生成的图自带水印,用 Pillow 把底部裁掉 100px 就行。**

## 3. 名片改造

个人简介从"记录工作、生活与学习"改成了:

> 温柔懒懒的海风,吹到高高的山峰

社交按钮也改成了**点击真实复制**:以前点 GitHub 按钮会弹"复制成功",但实际什么都没复制到——因为复制的是空字符串。现在六个按钮(GitHub / Gitee / Google / 邮箱 / QQ / 微信)都绑定了真实值,点一下就真复制,微信、QQ 这些在网页上也没法跳转,直接复制最实用。

## 4. 评论区:今天最大的坑

给博客加评论区,前前后后折腾了快两个小时。

### 4.1 第一方案 Gitalk:失败

一开始用 Gitalk,配置了 GitHub OAuth App,填好 Client ID 和 Secret,结果一直报:

```
redirect_uri mismatch
```

查了源码才发现,**Gitalk 把 `redirect_uri` 硬编码成了 `window.location.href`(当前页面地址)**,不受你控制。GitHub 新的 OAuth 规则下,多页面博客的 redirect_uri 子路径匹配一直报错,基本无解。果断放弃。

### 4.2 第二方案 Giscus:成功接入

换成 Giscus(基于 GitHub Discussions),配置就几个步骤:

1. 仓库开启 **Discussions**(Settings → General → Discussions)
2. 安装 **giscus app** 到仓库
3. 在 giscus.app 官网填仓库名,拿到 `data-repo-id` 和 `data-category-id`
4. 复制配置到组件里

接入成功后评论区能用了,但**丑**,而且**看不清**。

### 4.3 主题美化:连踩三坑

这是今天最折磨人的部分,前后改了 4 版:

- **第一版**:毛玻璃半透明背景(`rgba(255,255,255,0.55)`)→ 对比度太低,看不清
- **第二版**:透明度加到 0.92 → 还是看不清
- **第三版**:发现根本原因——**Giscus 的主题不是靠类选择器改的,而是靠 GitHub Primer 的 CSS 变量(`--color-*`)**!前两版写的 `.gsc-*` 选择器压根没匹配上。于是拉取官方 light.css 照变量机制重写,改半透明白 → 结果半透明叠加网页渐变背景,还是淡
- **第四版**:实色白底 `#ffffff` + 近黑文字,终于清晰了,但...**自定义主题 URL 缓存极难绕过**,`?v=2`、`?v=3` 加版本号都没用,Giscus 还是用旧的默认主题

最后干脆**放弃自定义 CSS,直接用 Giscus 官方内置主题 `light_high_contrast`**(白底黑字高对比),不加载外部文件,不存在缓存问题,一次到位。

**经验总结:Giscus 改主题,要么用官方内置主题,要么用 CSS 变量机制,别用类选择器;自定义主题有缓存问题,版本号不一定管用。**

### 4.4 切页评论区消失:SPA 路由的坑

换好主题后发现新问题:**看完第一篇文章的评论区,点进第二篇,评论区直接没了。**

原因:博客是 Next.js 客户端路由(SPA),点链接切页面时**浏览器不整刷**,Giscus 脚本只在第一次加载时执行了一次,路由变了它不会重新初始化。

修复:用 `usePathname()` 监听路由变化,每次 pathname 变了就清空容器、用 `document.createElement("script")` 重新创建 Giscus 脚本。从此切到任何一篇文章,评论区都会跟着当前地址重新加载。

> 小提示:新文章第一次访问时,评论区可能显示"暂无讨论",这是正常的——访客发第一条评论后会自动创建对应的 Discussion。

## 5. 意外收获:不用再手动传文件了

折腾中发现本机 `.git-credentials` 里存着 GitHub 凭据,之后我直接用 GitHub Contents API 把文件推送到仓库,再也不用在浏览器里手动拖文件上传了。对经常改博客的人,这招真的省事。

## 总结

今天学到的东西:

1. **AI 生图的水印用 Pillow 裁掉即可**
2. **Gitalk 的 redirect_uri 硬编码在源码里,多页面博客基本不可用**,评论系统选 Giscus
3. **Giscus 主题用 CSS 变量驱动,不是类选择器**
4. **Giscus 自定义主题缓存很顽固,优先用官方内置主题**
5. **Next.js SPA 下,动态组件要监听路由变化重新初始化**,不能指望脚本只加载一次

改博客的过程就是不断踩坑的过程,但每次踩完都更懂一点。下次再接再厉。
