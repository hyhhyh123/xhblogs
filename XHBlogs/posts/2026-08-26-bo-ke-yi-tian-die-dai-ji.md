# 博客一天迭代实录：从功能补全到首屏性能优化

今天给我的博客做了一轮"大扫除 + 大升级"。原本只想修个小 bug，结果一路干到了性能优化，从早到晚发布了十几个 commit。把这一天的功能清单、优化过程和踩的坑都记下来，既是总结，也方便以后查。

![博客首页首屏](/images/blog-2026-08-26/home.jpg)

## 一、功能篇：一天补全了哪些模块

**1. 音乐自动播放的"最终形态"**

修了一上午的自动播放问题。核心结论：**浏览器禁止"带声音的自动播放"**（Chrome/Edge/Safari 都是），这是硬策略，不是 bug。期间试过静音自动播放 + 首次交互解锁、全局点击兜底……最后全部砍掉，因为事件监听互相打架（点一下按钮触发两次事件、鼠标移动误触发恢复播放）。最终形态很朴素：**能自动播就自动播，不能就乖乖等用户点播放按钮**，播放/暂停纯按钮控制，不搞任何全局监听。交互简单了，反而什么问题都没了。

**2. 文章列表 + 标签系统 + SEO 基建**

- `/posts` 文章列表：分页（每页 6 篇）+ 标签过滤
- `/tags` 标签云：按文章数分三档大小配色
- SEO 三件套：`sitemap.xml`（26 个 URL）、`robots.txt`、`feed.xml`（RSS）
- 导航栏加了「文章」入口

**3. 杂谈 + 留言板 + 上一篇/下一篇**

发现一个隐藏了很久的坑：杂谈（chatters）目录从来没推上过 GitHub，导致首页和杂谈页一直显示"暂无记录"。补上数据后，顺手加了留言板 `/guestbook` 和文章详情页的上一篇/下一篇导航。

**4. 独立搜索页（全文搜索）**

之前首页搜索栏只能搜标题，这次升级成**全文搜索**——标题、描述、标签、正文全部可搜，命中片段高亮，还带"找到 N 篇"的结果统计。用 `/search?q=自主可控` 能直接搜到正文里的内容，旧版搜不到。

![搜索页全文命中：关键词在正文里高亮](/images/blog-2026-08-26/search.jpg)

**5. 在线写作后台 `/write`**

博客最实用的新功能：浏览器里直接写文章、发布、编辑、删除。走 GitHub API 推送到仓库，密码保护（环境变量配置）。还给它配了一套 Markdown 工具栏（标题/加粗/斜体/代码块/公式/表格……），写起来顺手多了。

**6. 照片墙：30 张照片批量上线**

从电脑里挑了 30 张照片（92MB），用脚本批量处理：去水印（用 Pillow 裁掉底部 11%）、压缩（长边 ≤1600px，压到 10.5MB），分 3 个相册推上线。照片墙从空白变成了"随手拍 + 收藏 + 素材"三个相册。

![照片墙三个相册](/images/blog-2026-08-26/photowall.jpg)

**7. 两个小改进**

- 首页文章轮播右上角加「查看全部 →」，直达文章列表
- 文章页评论区上方加「全文约 N 字 · 预计阅读 X 分钟」，用中文 350 字/分估算

![文章页：评论区上方的阅读信息行](/images/blog-2026-08-26/post.jpg)

## 二、性能篇：体检 53 分，传输 9.5MB 是怎么砍到 2.7MB 的

功能补完顺手给网站做了次"体检"（本地 Lighthouse，移动端模拟）。结果：**性能 53/100，首屏 6-10 秒，总传输 9.5MB**。

顺着数据挖出两个真凶：

**真凶一：网易云封面原图 7MB。** 首页音乐播放器直接加载了网易云返回的原图，这一张图就占了全站传输的 74%。修复：给图片 URL 加 `?param=500y500` 走网易云 CDN 缩略图，7MB 变几十 KB。

**真凶二：开屏动画把首屏内容"藏"了 3.5 秒。** 我站里的开屏动画逻辑是：整个页面初始 `opacity: 0`，等开屏播完才加 class 显示内容。新访客每次都要干等 3.5 秒。修复：时长 2.2s→1.2s、解锁延迟减半、**点击任意处可跳过**——效果保留，等待归零。

另外把三个纯装饰动效（弹幕、赛博猫、点击特效）改成**浏览器空闲时再加载**（`requestIdleCallback` + 动态导入），主线程阻塞时间直接减半。

**结果：总传输 9480 KiB → 2691 KiB（-71%）**，交互明显跟手了。

## 三、今天学到的硬核经验（踩坑合集）

1. **浏览器自动播放策略**：带声音自动播放基本必拦，硬刷新 = 新会话。别和浏览器斗智斗勇，交互简单才是王道。

2. **`next/dynamic` 的 `ssr: false` 不能用在 Server Component 里**（比如根布局 layout.tsx），Vercel 构建会直接失败。必须包一层 `"use client"` 组件再用。

3. **`requestIdleCallback` 的类型坑**：`'requestIdleCallback' in window` 这种写法会让 TypeScript 把 else 分支推断成 `never`，报 `setTimeout does not exist on type 'never'`。用 `typeof w.requestIdleCallback === 'function'` 判断就没事。

4. **React SSR 会在文本节点间插 `<!-- -->` 注释**，导致 curl 验证时精确 grep 匹配不到，要用模糊匹配。

5. **图片体积是第一性能杀手**：9.5MB 传输里 7MB 是一张图。任何外链大图，优先想办法出缩略图。

6. **本地 git 仓库坏了也能发布**：用 GitHub Git Data API（blobs → tree → commit → update ref）一次提交多个文件，配合"轮询 commit status 等 Vercel 部署完成 + curl 线上验证"的链路，完全绕开本地 git。

7. **中文文件名会让 Vercel 构建失败**（Linux 编码问题），文章文件一律用拼音命名。

8. **npm 包的类型声明也会坑人**：`lucide-react@1.34.0` 发布时忘了带 `.d.ts`，需要手写最小类型声明兜底。

## 四、下一步

功能上还留着几个坑位：PWA（可安装）、第三方访问统计、友链申请表单、照片墙在线传图。性能上，首页轮播封面用的是 Unsplash 外链，国内访问偏慢，打算换到自己的图床。

一天下来最大的感受：**个人博客的魅力就在于可以完全按自己的节奏打磨，每一处优化都看得见摸得着。** 下次继续。
